# 你需要理解的 v2 五个变化

本次工作是旧版本提交后的新研究。旧版本测试总分已经知道，因此不能把本轮称为完全未接触测试反馈的原始实验。新研究只用 train 内部划分和规定的 validation 确认；没有新 test 成绩，也不能据此承诺排行榜名次。最终实测结论以 `results/research_v2/final_summary.json`、实验表和 v2 报告为准，以下解释方法本身。

## 1. 预测目标是正确答案组，返回值仍是原候选索引

同题四个推理过程可能有两个或三个得到同一个数值答案。官方评分只看最后数值是否正确；不是必须挑中某一条唯一的“正确推理”。我们用未改动的 `parse_answer` 规范化答案，把相同答案的候选放进同一组。

旧选择器只挑单条最高分。新的比较同时检查单候选最大值、答案组最大值和组内 log-sum-exp。组最大值与屏蔽无效解析后的单候选最大值等价，不应算成新模型。log-sum-exp 可以给多个同答案候选增加权重；减去 `alpha * log(组大小)` 则控制这一奖励。它们是否有用取决于实验，不能把相关的推理轨迹当作独立证据。

`None` 解析结果不会获得正确分数；只要有有效候选，就不选 `None`。只有一个有效答案组时，根据课程“每题至少一个正确候选”的契约，可以确定应选该组。未知合成输入若全都不可解析，固定返回原索引 0，并报告诊断。这个规则依赖课程契约，不适用于没有正确候选保证的现实题库。

答案组交叉熵把正确答案组作为目标，保留组内多个正确候选。所有候选都有效且 `alpha=0, tau=1` 时，它与原多正例 listwise 损失等价；改变 mask、归一化或聚合才会改变具体优化问题。选出答案组后，还要返回组内最高分候选的原始索引 0-3，不能返回答案数值。

## 2. 非线性模型可以学习“什么时候信任多数答案”

旧模型已经含有同题 embedding 绝对差、余弦相似度和票型统计，所以不能说它完全没有候选关系信息。但其最后一层是线性加权，同题相同的统计量会在候选排序时相消，无法通过可学习交互表达“分歧大时少信多数票”。

MLP 在旧 2064 维关系特征上学习多层非线性；ResMLP 加入残差结构。Deep Sets 则先用共享网络编码每个候选，再把同题均值、最大值、与均值之差和乘积交给共享比较器。这里的池化只发生在同题四候选内，不跨题；模型没有候选位置编码。Attention 也只处理四个候选 token，不把 1024 个 embedding 坐标误当成 1024 个 token。

参数更多不自动代表更好。必须把解码变化、损失变化和架构变化拆开比较，并保留未提升或过拟合的结果。候选置换后，分数应随同置换；完全相同的并列分数采用原索引最小者，精确并列时存在明确的置换例外。

## 3. OOF 表示该题既没参与拟合，也没参与早停

主要方法使用同一套 train 内三折，整道题及四个候选一起划分。每个外折的训练部分再划出内部早停集合；选定 epoch 后，在整个外折训练部分重新训练。标准化也只在对应拟合部分计算。外折标签不能决定 epoch。

三个外折合成 OOF 预测后，可以在相同题上比较错误和方法差异。它比用全 train 模型给 train 打分可靠，但研究者根据 OOF 选过超参数以后，OOF 也含有选择偏差，不能宣称是无偏最终泛化成绩。多个 seed 复用同一批题，也不等于增加独立样本量。

只有先锁定的最多两个 finalist 才能做新的完整 validation 确认。看到 validation 后不重新开启搜索。hard 固定定义为至少两个不同有效答案；单正例子集只作标签相关的开发诊断，推理时不能知道一题有多少正确候选。

## 4. 置信度必须针对实际选出的答案组

旧校准器估计的是旧 argmax 选择正确的事件。换成新答案组选择器以后，这个事件已经改变，不能沿用旧校准器。

新的诊断先计算“实际所选答案组”的概率及其与其他组的差值。若选择方式与组概率最大值不同，不能直接拿最大概率冒充实际选择的置信度；差值甚至可能为负。Brier 分数和 ECE 用实际选择正确与否评估。模型输出概率不自动等于校准良好的正确率，正式接口也不能靠低置信度弃答。若另行拟合校准器，只能使用 train OOF，不能用 validation 标签拟合。

## 5. 一切额外模型和预处理都计入资源成本

CPU 推理资产包括权重、均值、尺度、配置、校准以及融合成员，不能只报压缩后的文件大小。硬上限是未压缩合计 16 MiB。最终时间需要包围新预测进程和独立官方评分进程，包含 import、载入和特征处理；单个矩阵乘法耗时不能替代正式流程计时。

神经模型在 PyTorch 中训练，导出为只含数值数组的 NPZ，正式推理使用 NumPy。合成测试和最终完整 validation 输入的 Torch/NumPy 对照要同时核对分数误差与最终候选选择；接近并列时，仅声称“误差很小”还不够。

本机资源检查只能证明在本机条件下的运行情况，不能冒充课程参考 Xeon 的认证。旧正式版本、原始日志和旧 checkpoint 保留；新的 test 重评及正式成绩更新按课程明确适用的流程处理，没有依据时只交付可复现研究版本与待确认状态。

## 本轮已保存的实测结果应怎样读

完整 validation 确认记录见 [validation_summary.json](../../results/research_v2/validation_summary.json)，只评估了事先锁定的两个新 finalist：

| 方法 | 全部题 | hard | 单正例诊断 |
|---|---:|---:|---:|
| 旧冻结版本 | 724/798 | 282/355 | 59/117 |
| Attention | 738/798 | 295/355 | 70/117 |
| Deep Sets | 740/798 | 297/355 | 68/117 |

按预注册的 validation 规则选择 Deep Sets；相对旧版本，多选对 16 题，其中 hard 多 15 题。完整题差异的按题配对 bootstrap 95% 区间为 +0.376 至 +3.512 个百分点，hard 为 +0.845 至 +7.887 个百分点。这支持当前开发集上的提升，但区间没有消除先前研究和选模带来的偏差。

不能据此断言 Deep Sets 家族普遍优于 Attention：它只在本次 validation 多对 2 题，单正例却少对 2 题；共同 train OOF 上，Attention 的三个固定 seed 的 hard 均值约 79.41%，Deep Sets 约 78.73%，方向相反。这里的 seed 比较复用相同题目，不是新数据。部署 seed 一直固定为 3036900957，没有选择最幸运的一次。

几个负结果也应记住：MLP 的 group-loss 对照为 1599/2114 hard，原 listwise 对照为 1612/2114，不能把“目标对齐”当作必然提分。Deep Sets 去掉学习到的池化交互得到 1655/2114，完整池化版本为 1654/2114；保留的统计特征仍包含关系信息，而且参数量改变，这组结果不能证明该池化结构有独立收益。唯一一次等权融合得到 1674/2114，低于同 seed 的 Attention 1687/2114，因此没有部署融合。

选中的 Deep Sets 完整资产实测 963,670 bytes（约 0.919 MiB），本机新预测进程加独立评分进程为 1.7397 秒。这些是 validation 和本机资源实测，不是新 test 成绩或参考机器认证。新的正式 test 与课程成绩更新保持关闭，旧正式提交继续可追溯。
