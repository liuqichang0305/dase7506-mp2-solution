# V3 architecture sources and original adaptations

Inspected on 2026-10-30 Asia/Shanghai (2026-10-29 UTC). This note records architecture provenance, not benchmark improvement. All task-specific training results belong in the experiment registry. The implementation was written for this repository from the mathematical structures below. No author implementation was copied, no pretrained weights were imported, and no external training examples were downloaded. Exact source commits, inspected files and license texts are retained in `results/research_v3/model-source-evidence.json`.

## TabM

Primary paper: Gorishniy et al., [TabM: Advancing Tabular Deep Learning with Parameter-Efficient Ensembling](https://arxiv.org/html/2410.24210v3), ICLR 2025. Sections 3.2–3.4 and 5.1 explain BatchEnsemble transformations, diverse first input adapters, shared batches, and why each member must have its own loss. The author repository was inspected at commit [`28e47ae301c92ec37787dde1ce923a0793f405b4`](https://github.com/yandex-research/tabm/tree/28e47ae301c92ec37787dde1ce923a0793f405b4). Relevant implementation: [`tabm.py`](https://github.com/yandex-research/tabm/blob/28e47ae301c92ec37787dde1ce923a0793f405b4/tabm.py), particularly `LinearBatchEnsemble`, `MLPBackboneBatchEnsemble`, and `TabM`. Its [license](https://github.com/yandex-research/tabm/blob/28e47ae301c92ec37787dde1ce923a0793f405b4/LICENSE) is Apache-2.0.

Our compact adaptation has three hidden layers of width 128 and four members. For member j, each hidden layer computes `activation(((x * r_j) @ W.T) * s_j + b_j)`. The shared matrix mixes features only after the first member-specific input multiplier. First-layer `r` values are independent random signs for raw numerical features; later `r` and all `s` start at one. Biases initially share values across members but remain independent trainable parameters. The output head is separate for every member. The architecture contains 309,828 trainable parameters with all 2,064 relation features.

Input is `[questions,4,2064]`; output is `[questions,members,4]`. Candidate order is not encoded. All members see the same questions. The trainer must average individual member losses; inference averages their answer-group probabilities. Averaging logits before loss or inference is a different method and is not supplied by this module. A synthetic test confirms distinct member outputs and nonzero gradients for each member's first adapter and head.

This is not the complete paper benchmark configuration: the author raw-numeric defaults are substantially wider and use many more members; numerical embedding modules and full hyperparameter tuning are omitted. The tiny model and question-group loss are resource- and task-specific adaptations.

## RealMLP-inspired network and preprocessing

Primary paper: Holzmüller, Grinsztajn and Steinwart, [Better by Default: Strong Pre-Tuned MLPs and Boosted Trees on Tabular Data](https://arxiv.org/html/2407.04491v3), NeurIPS 2024. Section 3 and Appendix A.1–A.2 were read. The simplified author implementation was inspected at commit [`a8c73f75dbeae4ab1ba5bc92372c444ffa0f766e`](https://github.com/dholzmueller/realmlp-td-s_standalone/tree/a8c73f75dbeae4ab1ba5bc92372c444ffa0f766e). Both [`mlp.py`](https://github.com/dholzmueller/realmlp-td-s_standalone/blob/a8c73f75dbeae4ab1ba5bc92372c444ffa0f766e/mlp.py) and [`preprocessing.py`](https://github.com/dholzmueller/realmlp-td-s_standalone/blob/a8c73f75dbeae4ab1ba5bc92372c444ffa0f766e/preprocessing.py) were read in full. Its [license](https://github.com/dholzmueller/realmlp-td-s_standalone/blob/a8c73f75dbeae4ab1ba5bc92372c444ffa0f766e/LICENSE.txt) is MIT, copyright David Holzmüller.

The original adaptation uses a learnable input scale initialized to one, three width-128 hidden layers with SELU, neural tangent parameterization `x @ W.T / sqrt(input_width) + b`, normally initialized hidden weights/biases, and a zero-initialized output head. It contains 299,537 parameters with all relation features. The zero head is intentional: export tests perturb the head to obtain a meaningful nonzero Torch/NumPy comparison, and a separate two-update synthetic check verifies gradients reach the learned input scale.

Robust preprocessing is fitted using only the caller's training partition. For each selected coordinate, the center is its median and the denominator is its interquartile range. A zero IQR falls back to half the observed range. A still-constant coordinate maps to zero, including future values. After scaling, `z` maps to `z / sqrt(1 + (z / 3)^2)`. The implementation uses the algebraically equivalent `hypot` form to avoid an unnecessary square overflow. Two distinct experimental settings are provided:

- `robust_stats`: robust-scale and smoothly clip the final 16 candidate-statistic coordinates; standardize the 2,048 embedding/relation coordinates.
- `robust_all`: robust-scale and smoothly clip all 2,064 coordinates.

`standard` retains the v2 mean/std rule for controls. Preprocessing is independent of inference batch composition. Every scaler and its clip/constant masks is exported as a numeric array, fitted again on the appropriate partition for nested early stopping and outer refitting. Optional architecture feature subsets (`embedding_stats` and `stats`) are explicit configurations; they are not inferred from performance.

The author TD-S recipe includes Adam beta2=.95, a larger base learning rate than a conventional MLP, an input-scale learning-rate multiplier of 6, a bias multiplier of .1 and a particular long schedule. These are separate optimizer/trainer choices, not silently enabled by constructing the architecture. This repository supports explicit settings and must record the settings used for each run. Width, group-ranking objective, nested early stopping and training budget differ from the authors' classifier. The model is therefore labelled RealMLP-inspired, not a complete reproduction of RealMLP benchmark results.

## Compatibility, export and synthetic checks

The existing MLP, ResMLP, Deep Sets, attention and linear implementations are imported from the frozen v2 module without modification. New bundles use the strict `mp2-research-v3` schema and cannot be mistaken for v1/v2 assets. Bundle writes refuse to overwrite an existing checkpoint. All trainable arrays and preprocessing arrays are included; optimizer state and external package caches are absent. NumPy inference imports no Torch. Linear inference retains float64; neural inference uses float32.

`code/tests/test_models_v3.py` reads no official train, validation or test data. Its six test methods passed in 2.177 seconds with Torch/BLAS threads limited to one. It exercises eight architecture configurations, candidate/row permutations, member diversity and gradients, robust formula/fallbacks, training-partition fit isolation, feature subsets, schema/finite/alignment checks, arbitrary IDs, empty inputs, a 137-question chunk boundary and float64 linear compatibility. The largest observed Torch/NumPy score difference was `5.960464477539062e-7`; group choices matched in these synthetic examples. This does not replace the final frozen-checkpoint full-input export and inference-contract audits. The actual console log is `results/research_v3/model-synthetic-tests.log` (PowerShell formats unittest stderr as a native-command record; process exit was 0 and every case passed).

Reproduce the synthetic checks from the repository root with the research environment: `.venv/Scripts/python.exe code/tests/test_models_v3.py`. Thread limits are set in the test before NumPy/Torch imports.
